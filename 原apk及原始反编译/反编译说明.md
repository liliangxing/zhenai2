# 珍爱网官方原版 APK 反编译说明

## 反编译结果概述

使用 **jadx 1.5.6** 对官方原版 APK（`com.zhenai.android` v9.29.5）进行静态反编译。

### 反编译出的内容

- `反编译源码/sources/` — Java 反编译源码（119 个类）
- `反编译源码/resources/` — 资源文件（res 目录，图片/布局/动画等，约 190MB）

### 反编译出的类构成

| 包 | 说明 |
|----|------|
| `com.alibaba.android.arouter.*` | 阿里开源路由框架 ARouter（Apache 2.0 协议，本身就是开源库） |
| `s.h.e.l.l.*` | 4 个混淆类 |
| `kotlin.coroutines.jvm.internal` | Kotlin 协程调试类 |

## ⚠️ 重要限制：业务代码被加固保护

**原 APK 的业务代码（`com.zhenai.*`）无法通过静态反编译还原。**

原因：原 APK 部署了**代码加固（加壳保护）**，证据：

1. **存在加固特征 so 库**：
   - `lib/arm64-v8a/libdexvmp.so` — dex 虚拟机保护（字节码抽取/虚拟化）
   - `lib/arm64-v8a/libzxprotect.so` — 加固保护壳
   - `lib/arm64-v8a/libmsaoaidsec.so` — 安全 SDK

2. **APK 内仅有 1 个 classes.dex**：正常的 App 业务量大应有多个 dex（复刻版有 8 个）。原 APK 只保留壳入口 dex，**真正的业务字节码在 App 运行时由加固壳解密加载**，静态分析阶段看不到。

### 这意味着什么

- `jadx`/`apktool` 静态反编译**只能拿到壳入口 + 少量未加固类**（即上面 119 个类）
- 要还原 `com.zhenai.*` 业务代码，必须**动态脱壳**（在已 root 的模拟器/真机上运行 App，等壳解密后从内存 dump 出真实 dex）
- 动态脱壳依赖特定设备环境，且涉及加固破解，不在本文档范围内

## 与复刻项目的关系

复刻项目（`/workspace`）的业务代码**不是**通过直接反编译获得的，而是根据：
1. 原 APK 的 **Manifest 组件清单**（本目录 `原APK-Manifest分析.txt`）
2. H5 端明文 JS（`zhenai-2.0.2.min.js`）的接口逻辑
3. 真实抓包的接口返回结构

综合复刻而来。因此复刻版是"接口行为一致、代码全新编写"的实现，而非原版代码拷贝。

## 反编译命令（供复现）

```bash
# 安装 jadx
cd /opt
curl -L -o jadx.zip "https://github.com/skylot/jadx/releases/download/v1.5.6/jadx-1.5.6.zip"
unzip jadx.zip -d jadx

# 反编译（-d 指定输出目录）
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
/opt/jadx/bin/jadx -d "反编译源码" 珍爱网官方原版APK-v9.29.5.apk --threads-count 4

# 查看反编译出的 Java 类
find 反编译源码/sources -name "*.java" | wc -l
```
